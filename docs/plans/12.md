## Goal
Customer-facing incidents receive the one-level priority increase regardless of when they are opened.

## Steps
1. Update `incidentdesk/priority.py` so the customer-facing priority adjustment does not depend on business hours; leave maintenance adjustment and routing behavior unchanged.
2. Update `tests/unit/test_priority.py` with one test for each priority-rules example, including the night and weekend cases, and preserve coverage for severity, maintenance, and timezone behavior.
3. Add a plain-language entry under Unreleased in `CHANGELOG.md`.

## Tests
- Tuesday 23:30, major, customer-facing `login-service` returns P1: assert in `tests/unit/test_priority.py`.
- Saturday 10:00, the same incident returns P1: assert in `tests/unit/test_priority.py`.
- Tuesday 14:00, the same incident returns P1: retain the existing example test in `tests/unit/test_priority.py`.
- Severity starts at the documented priority; maintenance lowers one level; P1 remains P1: retain the corresponding assertions in `tests/unit/test_priority.py`.
- Routing behavior does not change: run the existing tests in `tests/unit/test_routing.py` unchanged.

## Risks
Changing the priority independently of business hours could accidentally alter responder selection; the unchanged routing tests should catch that. Maintenance must still apply after the customer-facing increase.

## Out of scope
Stored incidents, routing logic, and `is_business_hours` behavior.
